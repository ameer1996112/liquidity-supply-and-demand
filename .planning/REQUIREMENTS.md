# REQUIREMENTS

## Core Value
Achieve a robust, highly reliable, clear, and maintainable trading system codebase that meets professional enterprise standards.

## Must-Haves (Table Stakes)

These are non-negotiable for completing this milestone:

- **Dead Code Removal**: Ensure all unused files, functions, and old feature branches are deleted.
- **Code Deduplication**: Centralize repetitive helper functions and utility codes.
- **Strict Adherence to DDD**: Standardize component boundaries across Frontend, Backend, and Worker layers.
- **Linting Compliance (Backend)**: Fix 100% of the 98 existing `ruff` warnings.
- **Linting Compliance (Frontend)**: Fix all active `eslint` errors and warnings.
- **Test Integrity**: Ensure all 11 backend tests pass, and fix the 1 failing frontend Vitest.
- **CORS Resolution**: Fix the production CORS policy issues blocking API execution.
- **Timeout Fixes**: Correct the MetaAPI 5s timeout and `yfinance` HTTP 404 blocking errors.

## Differentiators

- **Execution Speed**: Refactoring should directly reduce trade latency, making account/trade execution significantly more responsive.

## Anti-Features (Out of Scope)

- **New Algorithmic Strategies**: We are solely stabilizing the existing platform; no new algorithmic parameters or new trading signals are to be added in this phase.
- **Database Migrations**: No major schema changes to Supabase outside of what might be strictly necessary to fix broken existing state.
