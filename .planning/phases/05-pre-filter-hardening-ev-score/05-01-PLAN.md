**3b. Compute EV score in `_run_account_guards`, after the daily drawdown veto block (after line 1039, before the correlation guard at line 1041).**

Insert after the drawdown veto's except block (line 1039) and before the correlation guard comment (line 1041):

```python
    # ── EV Score (Phase 5: informational only, NOT gating) ─────────────
    # Compute after drawdown check so we have dd_pct available.
    try:
        entry = float(payload.get("entry", 0))
        sl = float(payload.get("sl", 0))
        tp = float(payload.get("tp", 0))

        if tp > 0 and sl > 0 and entry > 0 and abs(entry - sl) > 1e-8:
            estimated_rr = abs(tp - entry) / abs(entry - sl)
        else:
            estimated_rr = getattr(s, "default_estimated_rr", 2.0)

        composite_proxy = float(payload.get("score", 0)) * 100  # Pine score 0-1 -> 0-100

        # dd_pct: fraction of daily loss used (0.0 = no loss, 1.0 = limit hit)
        # Compute from the same values used in the drawdown veto above
        if daily_loss_limit_pct > 0 and acct_balance > 0:
            try:
                _ev_dd_pnl = _get_account_daily_pnl(profile)
                _ev_max_loss = -(daily_loss_limit_pct / 100.0) * acct_balance
                dd_pct = min(1.0, max(0.0, _ev_dd_pnl / _ev_max_loss)) if _ev_max_loss != 0 else 0.0
            except Exception:
                dd_pct = 0.0
        else:
            dd_pct = 0.0

        ev_score = (composite_proxy / 100.0) * estimated_rr * (1.0 - dd_pct)
        logger.info(
            "EV score: %.2f (composite_proxy=%.1f, rr=%.2f, dd=%.2f) [%s]",
            ev_score, composite_proxy, estimated_rr, dd_pct, account_name,
        )
        payload["_ev_score"] = ev_score
    except Exception as _ev_err:
        logger.warning("EV score computation failed for %s: %s", account_name, _ev_err)
```

**Important notes:**
- The `daily_loss_limit_pct` and `acct_balance` variables are already in scope from the drawdown veto block (lines 1010-1014). The EV score code reuses them.
- `_get_account_daily_pnl(profile)` is called a second time for dd_pct in EV score. This is acceptable because it's a simple Supabase query and the drawdown veto may have short-circuited (returned early) before reaching this point. Wrap in try/except for safety.
- Store `ev_score` in `payload["_ev_score"]` (underscore prefix = internal metadata, consistent with existing `_risk_multiplier_*` pattern). This makes it available to downstream logging/save_result without a DB migration.
- Do NOT add ev_score gating. This is informational only per CONTEXT.md.
