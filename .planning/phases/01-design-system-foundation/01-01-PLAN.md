    ```css
      --text-sm:   0.8125rem;   /* 13px — table cells, secondary text */

      --text-xl:   1.25rem;     /* 20px — section headings */
      --text-2xl:  1.5rem;      /* 24px — KPI values, large numbers */
      --text-3xl:  1.875rem;    /* 30px — hero metrics */
      --text-4xl:  2.25rem;     /* 36px — page-level hero numbers */

      /* ── Font Weights ────────────────────────────────────────────────────────── */
      --to-weight-normal:   400;
      --to-weight-medium:   500;
      --to-weight-semibold: 600;
      --to-weight-bold:     700;

      /* ── Semantic Font Roles ─────────────────────────────────────────────────── */
      /* Aliases map type roles to scale steps — use these in components */
      --to-label:   var(--text-xs);    /* uppercase labels, badges, KPI meta */
      --to-body:    var(--text-sm);    /* table cells, descriptions */
      --to-heading: var(--text-lg);    /* card/panel headings */
      --to-mono:    var(--text-sm);    /* monospace data values */
    ```

    NOTE on @theme inline registration for font sizes:
    Tailwind 4.x already registers --text-xs through --text-4xl internally. Defining matching values on
    :root overrides the defaults at the CSS variable level — no @theme inline entry needed for these.
    Do NOT add --text-* entries to @theme inline (would cause duplication).
    Font weight tokens (--to-weight-*) are not standard Tailwind tokens — they are consumed via
    `font-weight: var(--to-weight-semibold)` in CSS, or via inline styles in JSX. No @theme inline
    entry needed for Phase 1.
  </action>
