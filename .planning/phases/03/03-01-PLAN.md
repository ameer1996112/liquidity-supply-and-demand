# Phase 3: Frontend Optimization & Analytics - Plan

## Objective
Safeguard the React frontend from breaking on malformed arrays, fix Railway CORS blockers, and introduce autonomous prop-firm phase detection based on MetaAPI server mappings.

## Steps
1. **API CORS Update**: In `src/api.py`, allow broader CORS (handling explicit `CORS_ORIGINS` from env, or wildcards for `.up.railway.app`).
2. **Prop Firm Detection**: Update `src/services/prop_firm_detector.py` or the account syncer to regex `server_name` (e.g., `FTMO-Demo` -> "Eval", `FundedNext-Live` -> "Funded").
3. **Frontend Hardening**: Add optional chaining (`?.map`) and defensive checks (`Array.isArray(accounts)`) anywhere `accounts` is iterated in the frontend components (e.g. `frontend/src/app/accounts/page.tsx` or similar).

## Verification
- Test creating a manual test account payload that mimics a prop firm to assert the correct phase is assigned.
- Run frontend build (`cd frontend && npm run build`) to ensure no compilation errors.
- Ensure API runs successfully.
