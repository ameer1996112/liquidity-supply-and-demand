# Phase 3: Caching and Polish - Plan 02 (API Cache)

## Goal
Modify the `/challenge-status` endpoint in the backend to read from Redis before falling back to a direct Supabase calculation query.

## Requirements
- CACHE-01: challenge-status endpoint returns a cached response.
- DB fallback on cache miss.

## Implementation Steps
### 1. `src/api_prop_firm_v1.py` Modifications
- Inject or import the global Redis dependency.
- Inside `get_challenge_status`, attempt a `GET prop_firm:metrics:{account_name}`.
- If hit, deserialize and return immediately.
- If miss, compute the status as usual, write to Redis (30s TTL), and return the result.

## Verification
- Hit the endpoint multiple times in rapid succession. Notice the response times decrease and no DB hit occurs on consecutive requests.
